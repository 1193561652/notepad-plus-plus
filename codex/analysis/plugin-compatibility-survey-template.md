# Notepad++ v8.4.6 插件兼容性调查模板
## 1. 用途与填写规则

本模板用于执行插件系统移植指导中的 `PS-025`～`PS-028`。每个插件复制一份，
文件建议命名为：

```text
codex/analysis/plugins/<plugin-id>.md
```

调查以 Notepad++ v8.4.6 对应的插件列表为基线。先记录事实和证据，再评价兼容
难度；不能仅凭插件能够被 `LoadLibrary` 加载就判定兼容。

填写时遵守以下规则：

- JSON 中同一插件的 x86、x64、ARM64 条目合并调查，但分别记录版本、包和架构。
- 分析 JSON 指定的插件版本；分析其他版本时必须单独标明，不能混用结论。
- 有源码时以对应版本源码、构建文件和运行验证为主要证据。
- 无源码插件只标注源码缺失，不进行反汇编；可以记录公开文档、导入表、原版运行
  观察等非反汇编证据。重要插件另行标注，供后续按可观察行为复刻。
- `NPPM_*`、`NPPN_*`、`SCI_*` 和 Win32 能力尽量记录精确标识符，不使用
  “常用消息”“基本编辑功能”等模糊描述。
- 尚未核验的项目填写“未核验”，不能把缺少证据写成“未使用”。
- Windows x64 是代理窗口模型的优先实测平台；其他架构不得据此自动标记为已验证。

## 9. 兼容验收项

本节只记录后续验证要求。未实际执行的项目保持未勾选并注明所需平台。

### 9.1 最低安全基线

- [ ] 加载前识别平台和 CPU 架构不匹配。
- [ ] 六个必需导出及 `isUnicode` 返回值检查正确。
- [ ] 初始化、命令、通知、消息和关闭调用具备约定的异常边界。
- [ ] 日志能指出当前加载或回调的插件及失败阶段。
- [ ] `-noPlugin` 可以安全启动并跳过全部插件。
- [ ] 不兼容插件失败后保留文件，不自动删除。

### 9.2 加载与生命周期

- [ ] 动态库成功加载，插件名称和 `FuncItem` 数据通过校验。
- [ ] `setInfo` 获得主窗口和两个生命周期稳定的代理 HWND。
- [ ] 菜单命令 ID、名称、勾选状态和快捷键正确。
- [ ] `NPPN_READY` 等初始化通知的内容和顺序正确。
- [ ] 正常关闭时通知、清理和动态库卸载顺序正确。
- [ ] 连续启动、正常退出、再次启动无异常。

### 9.3 主要功能

- [ ] 插件主要用户工作流逐项通过。
- [ ] 当前文档、选区、文本修改和撤销行为正确。
- [ ] 主/副视图切换及目标视图语义正确。
- [ ] 所需 `NPPM_*` 的参数、返回值和错误值与原版一致。
- [ ] 所需 `SCI_*` 的缓冲区、指针、编码和同步语义正确。
