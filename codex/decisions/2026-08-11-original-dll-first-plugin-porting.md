# 决策：原版 DLL 优先与 Qt 插件重构

## 状态

已确认，2026-08-11。

## 决策

1. NppEditorConfig 0.4.0 和 AutoSave 1.6.1.0 首先尝试兼容官方未修改的原版
   Windows DLL，不预先改为 Qt 主程序内置功能。
2. NppTextFX 0.2.6 暂不选择原版 DLL 兼容、Qt 插件重构或主程序内置路线，留待
   后续处理时根据源码证据、功能清单和兼容成本单独决策。
3. 后续统计和规划中，重要插件若难以兼容原版 DLL，应优先保留插件形态，基于
   原插件源码和业务结构重构为 Qt 版插件。
4. “Qt 版插件”可以使用 Qt 实现跨平台 UI 和平台服务，但应通过插件 API/Host
   Services 接入，不把功能直接写入 Qt 主程序。
5. 只有功能被明确认定为编辑器核心职责并经过单独决策后，才采用 Qt 主程序原生
   实现。

## 理由

- 保持原版插件生态、功能所有权和代码结构边界。
- Windows 用户优先获得无需修改插件二进制的兼容路径。
- 原 DLL 确实受 Win32 窗口结构、运行时或不安全指针阻断时，Qt 插件重构仍可复用
  业务逻辑并覆盖 Linux/macOS。
- 避免为了单个插件持续扩大旧 Win32 兼容层，也避免把大量可选功能堆入主程序。

## 实施边界

- 原 DLL 兼容仍采用逐插件、逐消息、真实官方包验证，不承诺未知 DLL 安全兼容。
- 从 DLL 兼容切换到 Qt 插件重构前，记录阻断证据、所需 Host Services、保留的
  原业务模块、UI 替换范围和配置迁移方案。
- Qt 插件重构应尽量保持原插件的命令、配置文件、业务流程和可观察行为。
- NppTextFX 在决策前只做源码与功能取证，不实施架构性改动。

## 下一步

- 对 NppEditorConfig 和 AutoSave 定位 v8.4.6 清单对应的官方 x64 包及尽可能精确
  的源码版本，建立六导出、`NPPM_*`、`NPPN_*`、`SCI_*`、Win32 API 和线程矩阵。
- 分别安装并在独立进程执行加载、READY、核心命令、通知和退出测试；需要扩大架构
  或违反有限兼容原则时停止实现并记录。
